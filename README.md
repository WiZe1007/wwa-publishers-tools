# WWA Publishers Tools

Внутрішній сайт з інструментами для публікації додатків:

- **ZIP Creating** — упаковка матеріалів додатку в .zip з AI-генерацією ASO описів (Claude)
- **Resize the Image** — зміна розміру зображень точно по px
- **Convert Images** — конвертація зображень між форматами
- **Merge Images** — об'єднання кількох зображень в одне
- **Метадані** — локальне пакетне очищення JPEG, PNG, WebP та MP4/MOV/M4V, завантаження окремих копій або ZIP

## Локальний запуск

1. Встановіть [Node.js](https://nodejs.org) (версія 20+)
2. У папці проєкту:
   ```bash
   npm install
   ```
3. Створіть файл `.env` (скопіюйте з `.env.example`) та вставте ваш Anthropic API ключ:
   ```
   ANTHROPIC_API_KEY=sk-ant-...
   ```
4. Запустіть:
   ```bash
   npm start
   ```
5. Відкрийте http://localhost:3000

Без API ключа працюють усі сторінки, крім AI-генерації описів на ZIP Creating.

## Деплой на Render.com

1. Завантажте проєкт у GitHub репозиторій (`.env` НЕ комітиться — він у `.gitignore`)
2. На render.com: **New → Web Service** → підключіть репозиторій
3. Налаштування:
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Environment → Add Environment Variable:** `ANTHROPIC_API_KEY` = ваш ключ
4. Deploy. Render сам призначить порт (сервер читає `process.env.PORT`)

## Структура

### Відеофон

`public/js/backdrop.js` враховує розмір екрана, DPR, швидкість з'єднання та
`MediaCapabilities.decodingInfo`. Файли `mountains-*-v3` створені з оригінального
`319751.mp4`, не з попередніх стиснутих копій. Усі версії мають стабільні 30 fps,
H.264/yuv420p, обмежений піковий бітрейт, MP4 fast-start і не містять аудіо.

| Версія | Роздільність | Кодування | Розмір |
|---|---|---|---|
| Lite | 1920×1080 | x264 slow, CRF 20, maxrate 5M / bufsize 10M | 11,7 МБ |
| Desktop | 2560×1440 | x264 slow, CRF 20, maxrate 8M / bufsize 16M | 18,8 МБ |
| Mobile | 1080×1920 | x264 slow, CRF 21, maxrate 5M / bufsize 10M | 11,8 МБ |
| Ultra | 3840×2160 | x264 slow, CRF 22, maxrate 12M / bufsize 24M | 28,3 МБ |

Для портретного кадру використано crop `1216:2160:1152:0` перед масштабуванням.
4K вмикається лише для достатньо великих фізичних екранів, швидкого/невідомого
з'єднання та декодера з `supported`, `smooth` і `powerEfficient`. Без цих гарантій
вибирається 1440p або 1080p. На 3G — Full HD; Save-Data, 2G та reduced motion
вимикають автозапуск. Два 4-секундні вікна з понад 4% пропущених кадрів або
повторна буферизація знижують якість Ultra → Desktop → Lite зі збереженням позиції.
Діагностика доступна в `data-rendition`, `data-total-frames`, `data-dropped-frames`
відеоелемента. Монітор не працює під час паузи або у прихованій вкладці.
Пауза, кешування та один відеоелемент зберігаються між сторінками. Великі панелі
інструментів використовують тоноване скло без дорогого live backdrop blur;
розмиття лишається тільки у компактному верхньому меню.
При наступному перекодуванні змінюйте суфікс версії у файлах, JS і CSS:
сервер кешує версійоване медіа як `immutable` на рік.

## Як працює ZIP Creating

1. Користувач заповнює форму та додає файли (скріншоти, apk, aab, banner, icon тощо)
2. Стиснуті копії скріншотів + назва + опис відправляються на сервер → Claude генерує short/full description і, якщо скріншотів > 8, обирає 8 найкращих
3. Довгий опис автоматично перевіряється на переспам (аналог ASOMobile Text Analyzer:
   слово не має вживатися більше ліміту разів, стоп-слова не рахуються). Якщо переспам є —
   Claude переписує опис (до 3 спроб). Ліміт налаштовується env-змінною `SPAM_LIMIT` (за замовчуванням 5)
4. На сторінці є кнопка «Перевірити на переспам» для ручної перевірки відредагованого тексту
   з таблицею частотності слів
5. ZIP збирається прямо в браузері (великі apk/aab на сервер не завантажуються):
   скріншоти нумеруються 1..8, заповнюється How to Publish.txt, додаються всі файли

Release Package показує всі п'ять розділів одночасно на одній прокручуваній
сторінці. Майстер кроків та кнопки «Далі/Назад» не використовуються.

## Локалізація ASO (Localize)

Окрема сторінка приймає назву, короткий і повний описи та цільову мову.
Доступні 77 мов та їхні регіональні варіанти — 107 опцій разом; пошук за
українською, російською, англійською, оригінальною назвою або кодом локалі.
Результати видно під пошуком; пошук не скидає обрану мову. Підтримуються
`Spanish Mexico`, `Mexico Spanish`, `pt_BR`, вибір кліком або Enter,
перехід до результатів стрілкою вниз і скидання запиту Escape. Для арабської, івриту,
перської, урду та пушту результати мають напрямок справа наліво.
Кнопка «Перевірити без AI» перевіряє вставлений текст без генерації та без
звернення до Anthropic, показуючи повтори, частки й потрібне зменшення.
AI адаптує всі три поля, зберігаючи факти й обмеження з джерела. Назву бренду
можна залишити незмінною. Результат редагується, перевіряється повторно,
копіюється або завантажується як `aso-<locale>.txt`. Кнопка «Покращити текст з AI»
працює з поточним результатом та його мовою, а не перекладає джерело повторно.
«Копіювати повний опис» копіює лише текст без службових заголовків для зовнішньої перевірки.

Використовуються наявні `ANTHROPIC_API_KEY` та `ANTHROPIC_MODEL`; ключ лишається
на сервері. Тексти передаються серверу й Anthropic, про що повідомляє форма.
Без ключа доступний API перевірки тексту, але AI-адаптація повертає зрозумілу помилку.
Сторінка не пише тексти в localStorage; внутрішня навігація зберігає форму в пам’яті.

- `GET /api/localize/languages` — дозволені мови й ліміти.
- `POST /api/localize` — `{locale, title, shortDescription, fullDescription, preserveTitle?, mode?: 'localize' | 'repair', profile?: 'strict' | 'natural', qualityReview?: boolean, reference?: {title, shortDescription, fullDescription}}`.
- `POST /api/localize/check` — ті самі текстові поля, `locale` та `profile`, без AI-виклику.
- `profile` за замовчуванням `strict`; `qualityReview` у API за замовчуванням `false`, у формі увімкнено.

Ліміти результату: 30 / 80 / 4000 Unicode-символів із пробілами; джерела:
200 / 500 / 12000. Використовується `Intl.Segmenter`, для англійської — наявне
групування форм змістових слів. Для 26 інших мовних кодів використовується
серверний `@orama/stemmers` (без завантаження словників у браузер), плюс явні
групи артиклів/займенників іспанської, французької, німецької, італійської й португальської.
Для решти мов рахуються точні форми, про що повідомляє звіт.
Стемінг не є повною лематизацією: можливі хибні об'єднання та пропуски нерегулярних форм.
У строгому профілі (за замовчуванням) у повному описі дозволено максимум
`max(1, floor(wordCount * 0.025))` вживань будь-якого слова, включно зі службовими
(`de`, `el`, `the` тощо). Одиничні вживання не є повторами. Короткі поля
перевіряються на дублікати змістових слів зі списками службових винятків.
Профіль «Природний текст» перевіряє змістові групи за формулою
`max(3, floor(wordCount * 0.04))`, а службові слова залишає у звіті без блокування.
Для мов без списку службових слів тип позначено як невизначений, усі групи перевіряються,
а звіт показує попередження. Природний профіль не видається за строгий:
у ньому видно кількість груп, що перевищили б строгий поріг.

Окремо перевіряються точні повтори речень (від 4 слів) і фрази з 2–4 слів.
Фрази рахуються без перекриття, всередині речень/рядків; вкладені дублікати
з однаковою частотою згортаються. Від 3 повторів показується рекомендація;
від 4 повторів і 12% покриття — обов'язкова правка. Фрази лише зі службових слів
пропускаються. Таблиця перемикається між полями, словоформами, точними словами,
фразами й реченнями; є пошук і фільтр проблем. Рядки показуються порціями по 50,
але пошук завжди охоплює весь звіт (фрази — 30 найвиразніших повторів).

AI отримує кількість слів, допустиму кількість вживань та необхідне зменшення
для кожної проблемної групи разом зі складом її словоформ. Поріг — внутрішня евристика,
не офіційна політика магазину та не гарантія ранжування чи якості перекладу.

AI-редактор окремим викликом перевіряє природність, регіон, збереження функцій,
чисел і важливих обмежень. Його конкретні зауваження передаються наступній спробі.
Перша чернетка перевіряється навіть за наявності переспаму, щоб правки не руйнували
граматику. При повторних покращеннях факти звіряються з початковим `reference`.
Помилка редактора не дає статусу «готово», ручне редагування скидає його схвалення.
Перевірка без AI не підтверджує якість перекладу. AI-редактура теж може помилятися;
це додатковий контроль, а не гарантія чи підтверджена перевага над зовнішнім сервісом.

Генерація має максимум 5 викликів адаптації + 2 AI-редактури, загальний таймаут 150 секунд та максимум
2 одночасні генерації на процес. Скасування клієнтом перериває AI-запит.
Результат з невирішеними зауваженнями показується для ручних правок, але
не має `ready: true` і не експортується кнопками до успішної перевірки.
У разі помилки додаткового AI-виклику вже отриманий варіант зберігається з попередженням.
AI-виклики використовують поточний обліковий
запис Anthropic і його звичайний білінг.

## Очищення метаданих

На Resize, Convert та Merge кнопка «Очистити метадані результату» розміщена
після результатів і активується лише після успішної обробки. Вона працює з
готовими файлами: новими розмірами, вибраним форматом або об’єднаним зображенням,
ніколи не з оригіналами. Canvas/BMP-кодер уже відкидає вихідні EXIF/GPS/XMP/ICC;
очищена копія з нейтральною датою не перекодовується повторно, зберігаючи точні
байти результату, зокрема JPEG/WebP/BMP. Один файл доступний окремо, кілька —
як ZIP. Зміна налаштувань, джерел або новий запуск скидають старий результат
очищення; кнопку буде активовано після наступної успішної обробки.
Release Package та окрема сторінка Metadata зберігають свої кнопки очищення.

Окрема сторінка «Метадані» доступна у верхньому меню. Файли не надсилаються
на сервер; оригінали не змінюються. Очищені копії отримують суфікс `_clean`.
Підтримується до 50 файлів / 400 МБ разом: зображення до 32 МБ та 40 Мп
(до 16384 px на сторону), відео до 200 МБ. Анімовані PNG/WebP відхиляються.

Зображення повторно зберігаються через Canvas без вихідних EXIF/GPS/XMP/ICC;
JPEG/WebP можуть трохи змінитися через стиснення, колір — через вилучення
профілю. MP4/MOV/M4V очищуються без перекодування: службові блоки `udta`,
`meta`, `uuid`, `free`, `skip` затираються зі збереженням байтових зсувів,
дати `mvhd`, `tkhd`, `mdhd` обнуляються. Вміст медіапотоку не змінюється.
Це не гарантія анонімності: назви, видимий текст та дані всередині медіапотоку
не приховуються. Помилкові файли не включаються до ZIP.

Спільний модуль `public/js/metadata.js` також використовується в Release Package.
ZIP використовує фіксовані часові мітки й зберігає всі файли з однаковими
іменами під унікальними назвами. Черга та результати зберігаються під час
внутрішньої навігації, але не після перезавантаження вкладки.
